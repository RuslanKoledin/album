# M0: исследование OTP и QR-платежей в Кыргызстане

> Статус: `RESEARCH_READY`, коммерческое и юридическое подтверждение ожидается  
> Проверено: 22 июля 2026 года

Документ сокращает список кандидатов для alpha. Он не является договором,
публичной офертой или подтверждением production-интеграции: тарифы, sender ID,
API, фискализация и sandbox повторно подтверждаются письменно перед подключением.

## QR/payment

### Подтверждённые факты

- [ELQR Межбанковского процессингового центра](https://ipc.kg/digital-services/elqr/)
  создаёт единое пространство QR-платежей без привязки покупателя к одному банку
  или кошельку.
- [MBusiness](https://mbank.kg/mbusiness) принимает QR-оплату из MBANK и других
  приложений. По опубликованному MBANK
  [тарифу от 5 марта 2026 года](https://mbank.kg/news/o-vvedenii-tarifov-po-operaciyam-cherez-qr-kody-i)
  с 18 марта указаны `0,3%` для собственного QR и `1%` для QR стороннего банка.
- [O!Business](https://obank.kg/ru/for-business/business-management) предлагает
  QR-эквайринг для расчётного счёта. Страница
  [POS/ККМ](https://obank.kg/en/for-business/pos-terminals) сообщает о выдаче
  API-протоколов интеграции и напоминает о необходимости фискального чека для
  ELQR/POS-платежа.
- Акция O!Bank с нулевой комиссией для новых пользователей была ограничена по
  сроку. Она не используется в unit economics без нового письменного тарифа.

### Решение для alpha

Основной путь: `merchant ELQR QR → клиент оплачивает → оператор сверяет
поступление → вручную подтверждает оплату с audit record`.

Это позволяет проверить спрос и производство без преждевременного webhook и не
привязывает интерфейс к одному банковскому приложению. QR должен вести на
расчётный счёт ИП/ОсОО, а не на личную карту.

Shortlist для коммерческого сравнения:

| Приоритет | Кандидат               | Зачем проверять                                   | Что запросить письменно                                       |
| --------- | ---------------------- | ------------------------------------------------- | ------------------------------------------------------------- |
| 1         | MBANK MBusiness/MKassa | Публичный ELQR-тариф и знакомый рынку сценарий    | Merchant QR с суммой, возврат, реестр, ККМ, API/sandbox, SLA  |
| 1         | O!Business             | QR, расчётный счёт и заявленная API-поддержка POS | Действующий тариф после акции, dynamic QR, callback, ККМ, SLA |
| 2         | Другой участник ELQR   | Резерв и сравнение условий                        | Те же пункты по единой форме                                  |

Dynamic QR, payment intent, callback/webhook и автоматическое изменение статуса
заказа остаются вне alpha до получения подписанного API-протокола, sandbox и
правил проверки подписи.

## OTP/SMS

### Подтверждённые факты

- У [SMSPro/NIKITA](https://smspro.nikita.kg/kg/documents/smspro.nikita.kg-OTP-api.pdf)
  есть отдельный OTP API: авторизация через `X-API-KEY`, отправка по
  `transaction_id` и номеру, проверка кода и получение delivery status.
- [Twilio публикует доставку SMS в Кыргызстан](https://www.twilio.com/en-us/sms/pricing/kg),
  но на дату проверки исходящее сообщение с международного номера стоит
  `$0.4588` за сегмент без возможных дополнительных carrier fees. Для массового
  локального OTP это резерв, а не экономичный основной путь.

### Решение для POC

Первый кандидат — SMSPro/NIKITA. Twilio остаётся техническим fallback только
для сравнения доставляемости и аварийного переключения после расчёта стоимости.
Backend сохраняет provider-neutral интерфейс, чтобы смена поставщика не меняла
auth HTTP contract.

До выбора production-провайдера нужно получить:

- договор и цену OTP по основным сетям Кыргызстана;
- правила регистрации буквенного sender ID;
- delivery SLA и статистику по операторам;
- rate limits, timeout, retry и поддержку idempotency/transaction ID;
- data processing/retention условия и географию хранения логов;
- тестовый ключ и allowlist номеров;
- порядок возврата средств за недоставленные сообщения;
- аварийный контакт и регламент инцидента.

## Обязательный пилот

Пилот проводится минимум на трёх действующих сетях и не менее чем на 30
сообщениях на кандидата.

| Проверка          | Критерий                                                          |
| ----------------- | ----------------------------------------------------------------- |
| Доставка          | Не менее 95% тестовых OTP доставлены за 60 секунд                 |
| Повтор            | Resend не делает старый код снова валидным                        |
| Безопасность      | Код одноразовый, короткоживущий, хешируется и отсутствует в логах |
| Ошибка провайдера | UI получает безопасный recoverable status без раскрытия номера    |
| Стоимость         | Известна полная цена успешной авторизации, включая resend         |
| Наблюдаемость     | Есть provider request ID и delivery status без текста OTP         |
