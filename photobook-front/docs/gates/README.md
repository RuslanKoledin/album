# Исполнение проектных gates

Этот раздел превращает незакрытые внешние проверки roadmap в воспроизводимые
процедуры. Он не меняет scope milestone и не заменяет технические спецификации.

## Статусы

- `READY_TO_RUN` — процедура и тестовый стенд готовы, нужен фактический прогон.
- `WAITING_FOR_OWNER` — без назначенного внешнего владельца результат получить
  нельзя.
- `FAILED` — проверка проведена, критерий не выполнен и заведены исправления.
- `PASSED` — критерий выполнен, доказательства и ответственный зафиксированы.

## Текущая доска

| Gate                | Статус              | Что уже готово                                   | Следующее действие                                              | Источник результата                          |
| ------------------- | ------------------- | ------------------------------------------------ | --------------------------------------------------------------- | -------------------------------------------- |
| M0: производство    | `WAITING_FOR_OWNER` | Форма, протокол, shortlist типографий и опросник | Назначить owners и запросить техкарту у двух главных кандидатов | [M0 production gate](m0-production.md)       |
| M1/M3: backend      | `WAITING_FOR_OWNER` | Frozen frontend contracts, fixtures и checklist  | Backend owner выполняет приёмку и object-storage proof          | [Backend handoff](../api/backend-handoff.md) |
| M2: понятность flow | `READY_TO_RUN`      | Полный mock-flow и сценарий исследования         | Провести 5 отдельных сессий без подсказок                       | [M2 usability gate](m2-usability.md)         |

Статус в этой таблице меняется только вместе с заполненным источником результата.
Наличие кода, mock-ответа или документа само по себе не означает `PASSED`.
