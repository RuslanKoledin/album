### Технический контракт профиля

Backend уже содержит `PrintProfileV1`, который собирает геометрию, диапазон
разворотов и PDF/цветовые требования в одну неизменяемую структуру. Версия
выводится из хеша полного содержимого. Профиль со статусом `approved` невалиден
без timestamp и идентификаторов evidence, партнёра и Production owner.

Это только готовая форма переноса подтверждённой техкарты: production-профиль
ещё не создан, текущий mock-профиль не открывает render job, а статус M0
остаётся `WAITING_FOR_OWNER`.

Расчёт:

```text
variable_cost = print + binding + packaging + delivery + payment_fee
              + manual_labor + defect_reserve
gross_margin = sale_price - variable_cost
gross_margin_percent = gross_margin / sale_price * 100
```

Результат не является публичной офертой. Business owner отдельно подтверждает,
что маржа положительная и достаточна для alpha.

## 4. Контрольный PDF и физический образец

1. Зафиксировать commit и `BookDocumentV1` golden fixture.
2. Сгенерировать один PDF согласованным renderer без ручной правки файла.
3. Сохранить PDF, preflight report и checksum рядом с evidence.
4. Передать файл партнёру с записанными настройками печати.
5. Измерить trim, bleed, safe zone, fold/spine и положение контрольных меток.
6. Осмотреть обрез, разворот, цвет, резкость, шрифты, ламинацию и переплёт.
7. Сфотографировать образец с линейкой и записать найденные отклонения.
8. При исправлении повторить цикл с новым номером прогона; не перезаписывать
   предыдущие доказательства.
