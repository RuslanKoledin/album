# Шаблон отдельной задачи

Шаблон используется только для крупной, рискованной, многодневной задачи или
формального handoff. Небольшое изменение не требует отдельного task-файла.

```md
# <ID> — <Короткий результат>

## Контекст и цель

Почему задача нужна и какой проверяемый результат должен получить пользователь
или система.

## Scope

- Что входит.

## Out of scope

- Что намеренно не входит.

## Зависимости и решения

- Связанный milestone/gate.
- Утверждённые продуктовые и технические решения.
- Открытые блокеры, которые нельзя угадывать.

## Acceptance criteria

- [ ] Наблюдаемый критерий 1.
- [ ] Наблюдаемый критерий 2.

## План реализации

- Затронутые модули.
- Изменения данных, API, migrations или public contract.
- Security/privacy impact.
- Совместимость и rollback/restore.

## Проверки по риску

- Риск, который нужно защитить.
- Минимальный достаточный test level или ручная проверка.
- Targeted-команды.

## Evidence

- Изменённые файлы.
- Выполненные команды, exit status и краткий результат.
- Screenshot/video/PDF, если применимо.
- Обновлённые contracts/migrations/docs.

## Ограничения и ручная приёмка

- Известные ограничения.
- Непроверенные внешние зависимости.
- Шаги владельца продукта или production owner.
```

Не добавляйте unit, component, integration и browser tests одновременно только
ради заполнения шаблона. Каждый тест должен защищать отдельный реальный риск.
